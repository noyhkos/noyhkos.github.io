Tiro의 API·Webhook을 관리하는 개발자 콘솔입니다. 백엔드와 API 스펙을 협의하며 화면 구성과 기능 범위를 주도하고, 구현부터 배포까지 단독으로 맡아 화면 10개를 배포했습니다. 사내 Clean Architecture 컨벤션(Repository·DI)을 신규 저장소에 이식하고, TanStack Query로 서버 상태를 캐싱하며 뮤테이션 후 관련 쿼리를 무효화해 화면을 항상 최신 상태로 유지했습니다. 쿼리 키를 personal·team 스코프로 나눠 개인 자원과 팀 자원이 서로의 캐시를 건드리지 않게 했습니다. 쿠키 기반 SSR 세션 가드로 미인증 접근을 막고, 소셜 로그인 3종(Google·Microsoft·Apple)을 연동했습니다.

기업 고객이 구성원과 팀을 관리하는 B2B 조직 관리 화면을 개요·멤버·팀 3개 탭으로 구현했습니다. 멤버 초대와 권한 변경·제거, 팀 생성과 멤버 배정, 검색·정렬·통계까지 화면부터 API 연동까지 단독으로 맡았고, 탭 컴포넌트만 2,300줄 규모입니다. 검색은 디바운스로 입력마다 요청이 나가지 않게 했고, 팀 목록은 아코디언으로 접어 구성원이 많은 조직에서도 한 화면에 들어오도록 했습니다. 엔티티·API·리포지토리·유스케이스로 계층을 나눠 화면이 API 응답 모양에 직접 묶이지 않게 정리했습니다.

팀사주 (TeamworkMate)

Full-stack · 1인 개발 · 폴리레포 4개 · 디자인 시스템 직접 구축
Problem팀을 짤 때 역할 분담은 늘 감으로 정해집니다. 사주와 MBTI로 역할·궁합·팀 밸런스를 뽑아주는 재미용 리포트를 만들되, 그 뒤를 백엔드·인프라 과제로 삼았습니다.
Challenge분석 한 건이 1분이 걸려 응답이 47초까지 늘어졌고, LLM은 그럴듯하지만 우리 점수와 무관한 문장을 만들어냈습니다. 설명과 계산이 어긋나면 리포트 전체의 신뢰가 무너집니다.
SolutionSQS로 분리해 요청은 202로 즉시 반환하고 워커가 뒤에서 처리합니다. 메시지는 작업이 끝난 뒤에만 삭제해 워커가 죽어도 재처리되고, 3회 실패하면 DLQ로 격리됩니다. 점수는 전부 결정론 공식이고 모든 가감점에 근거를 붙여 저장하며, 최고·최저 궁합 쌍의 근거는 리포트에 그대로 노출됩니다. LLM에는 점수에 실제로 기여한 사실만 넘기고, 생성과 다른 모델이 문장별 주장을 근거와 대조해 통과한 것만 서빙합니다. 판정이 실패하면 결정론 템플릿으로 내려앉아, 검증되지 않은 문장은 나가지 않습니다.
Frontend컴포넌트 라이브러리 없이 디자인 시스템을 직접 만들었습니다 — 토큰, 프리미티브 7종, 규칙 문서, 라이브 레퍼런스 페이지. 모바일에서 실제로 깨진 것을 규칙으로 고정했습니다: iOS Safari는 16px 미만 입력에 포커스가 가면 페이지를 확대하고 되돌리지 않아 모든 컨트롤을 16px로 묶었고, 탭 타겟 44px은 패딩이 아니라 높이로 강제했습니다. 대기 화면은 팀원이 들어오는 구간에도 폴링하고, 리포트 생성 후 명단이 바뀌면 집합 비교로 감지해 재분석을 제안합니다.
